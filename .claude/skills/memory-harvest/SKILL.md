# memory-harvest — 메모리의 지적을 하네스로

## 절차

1. `python3 "${CLAUDE_SKILL_DIR}/scripts/list-memory.py"` — 두 하네스의 항목 전문과 색인 어긋남.
2. 이 저장소의 `memory-ledger.md`를 읽는다.
3. 항목마다 **판정**하고 **제안 표**를 사용자에게 보인다. 승인 전에는 하네스도 메모리도 고치지 않는다.
4. 승인된 것을 반영한다 — `harness-authoring` 스킬을 먼저 본다.
5. 반영한 항목은 메모리에서 지운다: 항목 파일과 `MEMORY.md`의 그 줄.
6. `memory-ledger.md`에 행을 더한다.
7. 커밋은 사용자 승인 후 — 하네스 델타와 원장 행이 한 단위다.

## 판정

**① 하네스가 다룰 일인가.** agent의 일하는 방식에 대한 지적만 올린다. 특정 티켓의 결정, 클러스터·도구의 사실은 메모리에 둔다.

**② 이미 하네스에 있는가.** 대상 하네스에서 같은 뜻의 문장을 찾는다.

- **없다** → 올린다. 자리는 아래 표.
- **있다** → 문구를 더하지 않는다. 주변을 줄이거나 hook·스크립트의 거부로 옮긴다.
- **반대로 말한다** → 그 문장이 정책 ADR에서 왔으면(`pilots.md` · ADR 코퍼스) 사용자에게 충돌을 알리고 ADR 경로로 갈지 묻는다.

**③ 원장에 있는가.** 전에 올린 것이 메모리에 다시 나타났으면 ②의 "있다"로 처리한다.

**자리**

| 지적의 모양 | 자리 |
|---|---|
| 그 agent의 모든 작업에 걸린다 | 규약(`CLAUDE.md`) 또는 역할 프롬프트의 한 줄 |
| 특정 파일·디렉터리를 다룰 때만 | `.claude/rules/`의 경로 규칙 |
| 특정 절차 안의 한 단계 | 그 절차의 스킬 |
| 예외가 없어야 한다 | hook·스크립트의 거부 |

ops-workflow는 루트 · `harness/design-partner` · `harness/adr-judge` 세션이 메모리 하나를 쓴다. 항목의 "Why"로 어느 역할의 일인지 가려 그 역할의 파일에 올린다. 가릴 수 없으면 묻는다.

메모리의 문장을 옮겨 적지 않고 대상 하네스의 문체와 절 구조에 맞춰 다시 쓴다. 항목 안의 "내 해석"은 근거로 삼지 않는다.

## 제안 표

```
| 하네스 | 메모리 항목 | 판정 | 자리 | 반영할 문장(또는 변경) |
```

판정: `올림` · `이미 있음 → 정돈/강제` · `정책 충돌` · `메모리에 둠` · `지움(낡음)`.

## 색인 어긋남

- **파일 없는 포인터** — 색인 줄을 지운다.
- **색인에 없는 파일** — 다른 항목처럼 판정하고, 남길 것이면 색인 줄을 더한다.

## 세션 기록

항목의 뜻이 불분명할 때만 본다. 메모리 디렉터리의 부모(`list-memory.py --paths`)에 있는 `*.jsonl`을 항목의 날짜·티켓 번호·인용구로 `grep`한다.

## 원장

`올림`과 `이미 있음 → 정돈/강제`만 적는다: 날짜 · 하네스 · 메모리 항목 · 처리 · 자리(파일과 절).
