# harness-authoring — 규약에는 agent 자기 작업의 최소 정보만

하네스 파일을 고치는 일은 두 독자를 갖는다. **agent**는 `CLAUDE.md`·역할 프롬프트·rules·SKILL.md를 읽고, **사람**은 `README.md`를 읽는다. 어느 문장이 어느 독자의 것인지 가르는 기준은 하나다.

**agent의 파일에는 그 agent가 자기 일을 하는 데 필요한 것만 담는다.** 설정이 어떻게 주입되는지, 무엇이 어떻게 막히는지, 설정을 올바르게 유지하는 규칙은 **사람의 책임**이고 사람의 문서에 간다. 잘못된 세팅으로 agent가 틀리게 움직였다면 고칠 것은 규약이 아니라 세팅이다 — agent에게 환경을 지키는 규칙을 주면 자기 일이 아닌 것을 지키려 들고, 그 문장들이 쌓여 규약이 환경 설명서가 된다.

## 1. 문장마다 둘을 묻는다

- **agent가 이것을 몰라도 자기 일을 할 수 있는가?**
- **이것은 사람의 책임인가?**

하나라도 "예"면 agent의 파일에서 뺀다. 뺀 것이 사람에게 필요하면 README로 옮기고, 아무에게도 필요 없으면 버린다.

## 2. 어디로 가는가

| 문장의 종류 | 자리 | 왜 |
|---|---|---|
| 자기가 쓰는 이름과 경계 — env var 이름, 쓰기 가능한 디렉터리, 티켓이 사는 저장소 | agent 파일 | 모르면 일할 수 없다 |
| 금지 · 요구 · 트리거 · 성공 경로 | agent 파일 | 강제 지점은 실패할 때만 말한다 — 미리 알아야 하는 것은 산문으로(`CLAUDE.md` §4) |
| 역할과 그 이유 | agent 파일 | 판단의 근거다 |
| 설정이 어디서 어떻게 주입되는가 (`settings.local.json`, gitignored, scope 병합) | README | 세팅은 사람의 것 |
| 설정을 올바르게 유지하는 규칙 ("절대경로를 하드코딩하지 않는다") | README | 세팅은 사람의 것 |
| 무엇이 어떻게 막히는가 (hook가 거부한다, PATH에 올린다, exit 코드 표) | README | 거부 사유가 그 자리에서 말한다 — 프롬프트가 되풀이하면 원천이 둘이 된다 |
| 사람의 문서를 가리키는 포인터 ("자세한 것은 README") | 버린다 | agent는 README를 읽지 않는다. 읽지 않는 문서를 가리키는 문장은 노이즈다 |

**README는 사람에게 쓴다.** 첫 줄에 "agent는 읽지 않는다"를 두면 규약이 그쪽으로 새는 것을 막는다. 반대로 agent 파일에 README가 등장하면 그 문장은 자리를 잘못 잡은 것이다.

## 3. 산문을 더하기 전에 — 강제 지점이 말할 수 있는가

규약에 문장을 더하려는 순간, 먼저 묻는다: **스크립트가 실패할 때 이것을 말해 줄 수 있는가? hook의 거부 사유에 넣을 수 있는가?** 가능하면 그쪽에 둔다. 산문은 강제 지점이 닿지 못하는 곳 — 미리 알아야 하는 금지·요구·트리거·성공 경로 — 에만 남긴다.

거부 문구를 쓰거나 고칠 때는 세 부분을 갖춘다: **무엇이 막혔나 · 왜(규약 절 번호) · 대신 무엇을 하나.** 셋 중 하나가 빠지면 agent는 우회로를 찾는다.

규약을 바꾸면 **그 규약을 말하는 거부 문구도 같은 커밋에서** 바꾼다. 한쪽만 고쳐지면 agent는 둘을 화해시키느라 틀린다.

## 4. SKILL.md를 새로 만들거나 개편할 때

`skill-creator:skill-creator`를 부른다.

## 5. 끝내기 전에

고친 파일을 한 번 더 읽으며 세 가지만 본다.

- agent 파일에 **설정·주입·강제 방식의 서술**이 남아 있는가 — 있으면 README로.
- agent 파일에 **README라는 단어**가 있는가 — 있으면 그 문장을 지운다.
- 같은 규칙이 **두 자리**에 있는가 — 한 자리만 남기고, 다른 쪽은 절 번호로 가리킨다.

## 예 — steward 자신의 §1

고치기 전:

> 대상 저장소 로컬 경로는 env var로 주입한다. `.claude/settings.local.json`(gitignored · PC별)의 `env`에 둔다. 새 PC: example 파일을 복사해 채운다. 절대경로를 하드코딩하지 않는다. ⚠ `env` 블록은 scope 간 치환이다.

고친 뒤:

> 대상 저장소의 로컬 경로는 env var `OPS_WORKFLOW_ROOT`·`TICKET_ENGINEER_ROOT`로 온다. 모든 스크립트·셸은 이 변수로 대상을 찾는다.

남은 것은 변수 이름 — agent가 일하려면 알아야 하는 것. 빠진 것은 전부 사람이 세팅하며 알아야 하는 것이고, README로 갔다.
