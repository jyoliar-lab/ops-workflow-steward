# coherence — 정책 정합성 감사

ops-workflow의 정책 ADR들이 서로 모순·충돌하지 않는지 감사한다. **수집은 스크립트, 판정은 너(agent)**다.

## 절차

1. `python3 "$CLAUDE_SKILL_DIR/scripts/collect.py"` 실행 → ADR 인벤토리 + 참조 그래프 + **후보 쌍**(subject/topic/parent 공유) JSON.
2. 후보 쌍을 우선, 그다음 전수로 각 쌍의 **본문을 읽어** 아래 유형으로 판정한다.
3. 충돌·의심 목록을 **사용자에게 보고**한다(근거 ADR id + 유형 + 발췌). **`docs/`에 보고서를 쓰지 않는다** — 터미널 + 필요 시 이 저장소의 감사 로그.

## 충돌 유형 카탈로그 (판별 질문)

- **① 직접 모순** — A가 X를 규정하고 B가 ¬X. → *두 규범을 동시에 만족시킬 수 있는가? 불가면 모순.*
- **② 같은 축 상이 분할** — A와 B가 같은 대상을 다르게 자른다(경계·분류·명명). → *같은 것을 가리키는데 서로 다른 경계/이름을 주는가?*
- **③ 전제 붕괴** — A의 "왜"가 B가 부정한 무엇에 의존한다. → *A의 근거가 B가 뒤집은 전제에 기대는가?*
- **④ 공동무효 경계 위반** — 함께 죽어야 할 것이 두 ADR로 갈렸거나, 독립적인 것이 한 ADR에 묶였다. → *"X가 뒤집힐 때 Y도 반드시 무효인가?" 예인데 갈렸으면 / 아니오인데 묶였으면 위반.*

> 이 카탈로그는 steward의 **감사 방법론**(도구)이지 ops-workflow 정책이 아니다. 정책 내용이 바뀌어도 이 유형들은 유효하다.

## 판정은 기계가 아니다

`collect.py`는 **수집만** 한다(무엇을 비교할지 좁힌다). **충돌인지 아닌지는 네가 본문 맥락으로 판정**한다. `candidate_pairs`에 없는 쌍도 놓치지 말고 전수 확인을 권장한다. 애매하면 판단 근거를 제시하고 **사용자에게 묻는다.**
